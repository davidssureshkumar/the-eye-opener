# PHYSICS.md

Every formula this site implements, with its source or derivation, its assumptions,
and the range over which it is valid.

This file is the technical record. If a relationship appears on the screen, it is
here; if it is here, it is implemented and covered by a test. Where an
implementation is an approximation, it says so and says how large the error is.

**Provenance rule.** No numeric value in this project is taken from a JEDEC
document, a vendor datasheet, or any other controlled specification. Standards are
cited by document number only. Default values in the UI are representative of a
class of interface and are labelled illustrative; they are not specification
figures. Where a _polynomial_ or a _definition_ comes from a public standard
(ITU-T O.150, IEEE 802.3), the standard is named.

Scope: this file currently covers the layers implemented in Milestone 1 — DSP,
plotting mathematics, and scenario state. Channel physics (transmission lines,
skin effect, dielectric loss, crosstalk, equalization) is specified in the module
plan and will be added to this file as each module is built, not before.

## 1. Conventions

| Quantity          | Symbol      | Unit  | Notes                                    |
| ----------------- | ----------- | ----- | ---------------------------------------- |
| Frequency         | f           | Hz    | Never rad/s in a public API.             |
| Angular frequency | ω = 2πf     | rad/s | Internal to filter evaluation only.      |
| Time              | t           | s     |                                          |
| Symbol rate       | f_s         | Bd    | Symbols per second, not bits per second. |
| Unit interval     | UI = 1/f_s  | s     |                                          |
| Nyquist frequency | f_N = f_s/2 | Hz    | Where channel loss is quoted.            |

All SI, all base units internally. Engineering prefixes exist only at the
formatting boundary (`src/plots/scale.ts`).

**Amplitudes** are single-ended peak-to-peak volts unless stated. **Rise times** are
stated with their reference levels every time, because 20–80 % and 10–90 % are both
in common use and differ by a factor that depends on the edge shape (for a
single-pole response, t_10-90 / t_20-80 = ln(9)/ln(4) ≈ 1.585).

### DFT convention

Implemented in [src/dsp/fft.ts](src/dsp/fft.ts):

```
Forward:  X[k] = Σ_{n=0}^{N-1} x[n] · exp(−2πi·kn/N)      (unnormalised)
Inverse:  x[n] = (1/N) · Σ_{k=0}^{N-1} X[k] · exp(+2πi·kn/N)
```

All of the 1/N is in the inverse. Parseval's relation in this convention is

```
Σ |x[n]|²  =  (1/N) Σ |X[k]|²
```

and the test suite asserts it directly.

**Implementation.** Radix-2 Cooley–Tukey, decimation in time, in place, for
power-of-two lengths; Bluestein chirp-z for all other lengths, so the public API
accepts arbitrary N. Twiddle factors are evaluated directly into a cached table
rather than generated by recurrent rotation: the recurrence accumulates phase error
of order 10⁻¹⁰ at N = 2¹⁶, which is enough to visibly corrupt a deep bathtub curve.

## 2. Fourier series and the Gibbs phenomenon

Implemented in [src/dsp/fourier.ts](src/dsp/fourier.ts). Module 1.

### 2.1 Harmonic coefficients

Unit-amplitude bipolar waveforms (±1), sine basis, odd about t = 0:

| Shape         | Coefficient                          | Harmonics | Roll-off            |
| ------------- | ------------------------------------ | --------- | ------------------- |
| Square        | aₙ = 4/(nπ)                          | odd only  | 1/n, −20 dB/decade  |
| Triangle      | aₙ = 8/(n²π²), alternating sign      | odd only  | 1/n², −40 dB/decade |
| Sawtooth      | aₙ = 2/(nπ)                          | all       | 1/n                 |
| Pulse, duty d | aₙ = (4/(nπ))·sin(nπd), plus DC 2d−1 | all       | 1/n, with nulls     |

Derivation: standard Fourier analysis of each waveform over one period; these are
textbook results, not fitted.

The pulse coefficients are phased by π/2 − nπd so that the rising edge sits at
t = 0, matching the square wave's convention. **At d = 0.5 the pulse reduces term
for term to the square wave**, and the test suite asserts exactly that — it is the
cheapest available check that the phase convention is consistent.

**Valid for:** ideal periodic waveforms with zero rise time. A real edge is covered
in §3.

### 2.2 Gibbs constant

The partial sum of the square-wave series overshoots by a fixed fraction that does
**not** diminish with the number of harmonics — it only moves closer to the
discontinuity. The limit is the Wilbraham–Gibbs constant:

```
lim_{N→∞} max S_N(x)  =  (2/π) · Si(π)  =  1.178979744472...
```

for a square wave of amplitude 1 (a jump discontinuity of 2). Therefore:

| Quantity                                     | Value                          |
| -------------------------------------------- | ------------------------------ |
| Overshoot as a fraction of the **amplitude** | 0.1789797444721672 (17.8980 %) |
| Overshoot as a fraction of the **jump**      | 0.0894898722360836 (8.9490 %)  |

The familiar "about 9 %" refers to the **jump**. Both constants are exported and the
test suite re-derives them from the sine integral rather than trusting the literals.

> **Resolved at the Milestone 1 gate.** The brief states 8.93 %; the exact
> Wilbraham–Gibbs value is 8.9490 % of the jump. The exact value stands, in code and
> in prose. There is nothing to choose between here — 8.93 % is not a different
> convention, it is the same constant quoted short — and a course whose first module
> is about where the overshoot comes from cannot then print a rounded version of it.
> `src/dsp/__tests__/fourier.test.ts` re-derives both constants from Si(π), so the
> literals above are checked rather than trusted.

### 2.3 Sine integral

```
Si(x) = ∫₀ˣ sin(t)/t dt
```

Implemented in two regimes: the alternating series
Si(x) = Σ_{k≥0} (−1)ᵏ x^(2k+1) / ((2k+1)·(2k+1)!) for |x| ≤ 16, and the asymptotic
form Si(x) = π/2 − f(x)cos(x) − g(x)sin(x) with rational auxiliary functions above
it. Accuracy is better than 10⁻¹⁵ relative across the range used.

Present so §2.2 is a derived result rather than a copied constant.

### 2.4 The convergence reference and the error metric

`idealWave` returns the waveform a partial sum converges to, on the grid
`synthesize` uses. **At a jump it returns the midpoint of the two one-sided limits,
not either limit.** That is Dirichlet's theorem, not a rounding convention: where f
has a jump, the Fourier series converges to

```
½ · [ f(x⁺) + f(x⁻) ]
```

which for the bipolar square wave is 0 at the transitions. Taking +1 there instead
would charge the partial sum an error of 1 at the discontinuity for every N forever,
which would swamp exactly the behaviour the metric exists to show.

`rmsError(y, ideal)` is the discrete L² norm of the difference,

```
e_rms(N) = sqrt( (1/M) · Σ_i [ S_N(x_i) − f(x_i) ]² )
```

and it **does** go to zero as N grows, while the peak overshoot of §2.2 does not.
There is no contradiction: the Gibbs lobe keeps its height but narrows in proportion
to 1/N, so its energy vanishes. Showing both numbers together is what separates
"the series converges" — in the mean — from "the edge stops overshooting", which it
never does. Convergence in L² does not imply uniform convergence, and this is the
standard counterexample.

## 3. Edges, bandwidth and the knee

### 3.1 Knee frequency

```
F_knee = 0.5 / t_r          (t_r is the 10–90 % rise time)
```

Source: Johnson & Graham, _High-Speed Digital Design_. This is a rule of thumb
about **edges** — "how much bandwidth does this edge occupy" — and is deliberately
distinct from the −3 dB bandwidth of a filter, which answers "what bandwidth do I
need to reproduce this edge". Conflating the two is a standard way to over- or
under-specify a channel, and the site keeps them as separate functions for exactly
that reason.

**Valid for:** estimating spectral occupancy to within a factor of about 1.5. It is
not a measurement.

### 3.2 Rise-time–bandwidth product

The familiar BW = 0.35/t_r is a single-pole result quoted as if it were universal.
It is not. [src/dsp/filters.ts](src/dsp/filters.ts) computes the product
t_r · BW **per response shape**, exactly where a closed form exists and numerically
from the actual step response otherwise:

| Response             | t_r·BW (10–90 %)            | Source                        |
| -------------------- | --------------------------- | ----------------------------- |
| Single-pole RC       | ln(9)/2π = 0.349699         | Closed form, derived below    |
| Gaussian             | 2·z₉₀·√(ln 2)/2π = 0.339624 | Closed form, derived below    |
| Butterworth, order n | numerical                   | Solved from the step response |
| Bessel, order n      | numerical                   | Solved from the step response |
| Brickwall            | numerical                   | Solved from the step response |

**RC derivation.** Step response 1 − e^(−t/τ) with τ = 1/(2π·BW). Crossing 10 % at
t = τ·ln(10/9) and 90 % at t = τ·ln(10), so t_r = τ·ln 9 = ln(9)/(2π·BW).

**Gaussian derivation.** |H(f)| = exp(−a f²) with a = ½·ln 2 chosen so
|H(BW)| = 1/√2. The impulse response is Gaussian with σ_t = √(ln 2)/(2π·BW), so the
step response is the normal CDF and the 10–90 % interval is 2·z₉₀·σ_t, where
z₉₀ = 1.2815515655 is the 90th percentile of the standard normal.

**Reference levels are a parameter, not a constant.** `riseTimeBandwidthProduct`
takes `lo` and `hi` as fractions of the final value and defaults to 10–90 %, the
convention behind the familiar 0.35. Fast-interface datasheets increasingly quote
20–80 % instead, and the two are not interchangeable:

| Response             | t_r·BW (10–90 %) | t_r·BW (20–80 %) | Ratio |
| -------------------- | ---------------- | ---------------- | ----- |
| Single-pole RC       | 0.349699         | 0.220636         | 0.631 |
| Gaussian             | 0.339624         | 0.223038         | 0.657 |
| Butterworth, order 4 | 0.387139         | 0.269016         | 0.695 |
| Bessel, order 4      | 0.350159         | 0.236240         | 0.675 |
| Brickwall            | 0.445381         | 0.316651         | 0.711 |

The closed forms generalise directly. For the RC case the crossings are at
t = τ·ln(1/(1−p)), so

```
t_r · BW = ln((1−lo)/(1−hi)) / 2π            →  ln(4)/2π = 0.220636 at 20–80 %
```

and for the Gaussian, whose step response is the normal CDF,

```
t_r · BW = (z_hi − z_lo)·√(ln 2) / 2π          →  2·z₈₀·√(ln2)/2π = 0.223038 at 20–80 %
```

with z_p the p-th percentile of the standard normal (z₈₀ = 0.8416212). Note that the
ratio between the two conventions is **shape-dependent** — 0.63 for a single pole,
0.71 for a brick wall — so converting a measured 20–80 % rise time to a 10–90 %
figure with a single fixed factor is only valid if the edge shape is known.

The numerical cases are solved once per (type, order, levels) and cached. Quoting a
remembered table here would be precisely the kind of invented number this project
forbids.

### 3.3 Analogue response shapes

All normalised to **unity DC gain** and a **−3 dB point at `bw`**, so they are
directly comparable.

| Type                 | Transfer function                                 |
| -------------------- | ------------------------------------------------- |
| Brickwall            | H(f) = 1 for \|f\| ≤ BW, else 0. Zero phase.      |
| RC                   | H(s) = 1/(1 + s/ω_c), s = j2πf                    |
| Butterworth, order n | H(s) = 1/Π_k (s − p_k), p_k = exp(jπ(2k+n−1)/2n)  |
| Bessel, order n      | H(s) = a₀/θₙ(s), θₙ the reverse Bessel polynomial |
| Gaussian             | \|H(f)\| = exp(−½·ln2·(f/BW)²), zero phase        |

Reverse Bessel polynomial coefficients:

```
θₙ(s) = Σ_{k=0}^{n} a_k s^k,     a_k = (2n−k)! / (2^(n−k) · k! · (n−k)!)
```

The Bessel response is maximally flat in **group delay**, not in magnitude, which is
why it does not add overshoot to a step that did not have one, and why it is the
front-end shape of choice when edge fidelity matters more than selectivity.

The delay-normalised Bessel polynomial is not bandwidth-normalised, so the −3 dB
frequency scale factor is solved numerically (80 bisection steps) once per order and
cached.

**Brickwall is physically unrealisable** and is included precisely so a module can
show the sin(x)/x pre-ringing it produces — ringing that appears _before_ the edge,
which is the visual proof that the filter is not causal.

### 3.4 RLC step response

For the series-R, series-L, shunt-C network, with

```
ω₀ = 1/√(LC)            (rad/s)
ζ  = (R/2)·√(C/L)       (dimensionless damping factor)
```

the step response is under-damped (ζ < 1, ringing at ω_d = ω₀√(1−ζ²)), critically
damped (ζ = 1), or over-damped (ζ > 1), with the standard closed forms for each
regime. Fractional overshoot for ζ < 1:

```
overshoot = exp(−πζ/√(1−ζ²))
```

**Assumption:** lumped element. Valid while the physical size of the structure is
small compared with the wavelength at the knee frequency — roughly, while the
propagation delay across it is under about a tenth of the rise time. Beyond that,
the transmission-line treatment (Module 3) is required and the lumped model
understates what happens.

### 3.5 Group delay

```
τ_g(f) = −dφ/dω
```

Computed by central difference on the unwrapped phase. Phase is unwrapped before
differencing; differencing wrapped phase produces a spike of 2π/Δω at every
wrap, which is a classic silent error in a group-delay plot.

### 3.6 Applying a response to a waveform

`applyResponse` filters by **multiplying the spectrum**, not by running a difference
equation:

```
y = IDFT{ X(f) · H(f) }
```

The responses of §3.3 are defined analytically as H(f), and two of them — brick wall
and Gaussian — are zero-phase, with impulse responses that extend symmetrically in
both directions and cannot be realised causally at all. Spectral multiplication
applies each one exactly, so when two edge shapes are compared on screen the only
difference is the shape, not the quality of somebody's filter implementation.

**Wrap-around and the guard band.** The DFT treats the record as periodic, so the
end of the signal convolves into its beginning: on a bit stream that ends high and
starts low, the filter sees a step that is not in the data, and the first bit shows
ringing that the channel never produced. The signal is therefore embedded in a
longer buffer — a leading guard filled with x[0], the signal, then a raised-cosine
blend from x[n−1] back to x[0]:

```
w(i) = ½·[1 − cos(π·(i+1)/tail)],   i = 0 … tail−1
b    = x[n−1] + (x[0] − x[n−1])·w(i)
```

The raised cosine is continuous in value **and in slope** at both ends, so the
periodic extension contains no discontinuity of its own. The buffer is padded to the
next power of two, transformed, multiplied, inverted, and the guard cropped away.
The guard defaults to 8/BW — eight time constants of the response — which puts the
residual wrap below the arithmetic noise of the transform. The Nyquist bin is forced
real before the inverse transform, since a complex value there would make the result
non-real.

**Assumptions, stated because they are the ones that fail first on a real driver.**
The model is linear and time-invariant. There is no slew-rate limit, no output
compression, and rise and fall are the same shape. A slew-limited driver does not
obey this: its edge rate is set by a current and a capacitance, so its rise time does
**not** scale with amplitude the way these edges do. Module 2 says so on screen where
the distinction matters.

## 4. Pseudo-random sequences

Implemented in [src/dsp/prbs.ts](src/dsp/prbs.ts).

A PRBS-n built on a primitive polynomial of degree n is maximal length: period
2ⁿ − 1, every non-zero register state visited exactly once.

| Sequence | Polynomial             | Source              |
| -------- | ---------------------- | ------------------- |
| PRBS7    | x⁷ + x⁶ + 1            | SerDes convention   |
| PRBS9    | x⁹ + x⁵ + 1            | ITU-T O.150         |
| PRBS11   | x¹¹ + x⁹ + 1           | ITU-T O.150         |
| PRBS13   | x¹³ + x¹² + x² + x + 1 | OIF-CEI / PCIe PAM4 |
| PRBS15   | x¹⁵ + x¹⁴ + 1          | ITU-T O.150         |
| PRBS20   | x²⁰ + x³ + 1           | ITU-T O.150         |
| PRBS23   | x²³ + x¹⁸ + 1          | ITU-T O.150         |
| PRBS31   | x³¹ + x²⁸ + 1          | IEEE 802.3          |

Fibonacci LFSR form. Where a standard defines its sequence with a particular seed or
inversion, that is a property of the standard and not of the polynomial; this
library generates the raw maximal-length sequence.

**Properties asserted by the test suite**, all of which are theorems about maximal-
length sequences rather than measurements:

- Period is exactly 2ⁿ − 1.
- Ones density is 2^(n−1)/(2ⁿ−1) — one more one than zero over a full period.
- Longest run of identical bits is n (a run of n ones; the longest run of zeros is
  n−1).
- Run-length histogram: of the 2^(n−1) runs in one period, half have length 1, a
  quarter length 2, an eighth length 3, and so on.
- Periodic autocorrelation is 1 at zero shift and exactly −1/(2ⁿ−1) at every other
  shift. This two-valued autocorrelation is why a PRBS behaves like broadband noise
  in the channel while remaining exactly reproducible.

A zero seed would lock the register, so it is remapped to all-ones.

## 5. Test patterns

Implemented in [src/dsp/patterns.ts](src/dsp/patterns.ts).

Deterministic patterns (clock, divided clock, lone one/zero, walking one/zero,
all-ones, all-zeros, burst-idle, custom) are constructed directly and need no
justification beyond their definitions, which are in the source.

### 5.1 Worst-case ISI by peak-distortion analysis

The received sample at the cursor of bit 0 is

```
r = Σ_k a_k · h[−k]
```

where a_k ∈ {−1, +1} is the bipolar symbol of bit k and h[m] is the pulse response
sampled m UI after the cursor. Bit k contributes through tap m = −k, so **post-cursor
taps (m > 0) are driven by bits transmitted before the cursor bit** and pre-cursor
taps (m < 0) by bits transmitted after it. Getting that inversion backwards is the
most common error in hand-built worst-case patterns.

To minimise r for a transmitted 1, every other bit takes the sign that subtracts:

```
a_{−m} = −sign(h[m])
```

giving the peak-distortion bound

```
r_worst = h[0] − Σ_{m≠0} |h[m]|
```

This is the classic peak-distortion result (Lucky). An eye closed by this pattern is
closed **by construction**; no PRBS of finite length is guaranteed to contain the
sequence, which is why a link can pass PRBS31 and still fail on traffic.

**Assumption:** linear, time-invariant channel, and a pulse response sampled at
exactly 1 sample/UI at the chosen cursor phase. The bound is exact under those
assumptions and is optimistic if the channel has any non-linearity.

## 6. Statistics, noise and jitter

Implemented in [src/dsp/random.ts](src/dsp/random.ts).

### 6.1 Reproducibility

A single master seed derives labelled sub-streams (`subStream(seed, 'rj')`). Every
stochastic quantity draws from its own stream, so changing the noise amplitude does
not change which jitter samples are drawn. Without this, every slider move
reshuffles every random quantity and nothing can be compared with anything.

Gaussian samples come from the Box–Muller transform on a counter-based generator.

### 6.2 Error function and the Q-function

```
Q(x) = 1 − Φ(x) = ½·erfc(x/√2)
Φ(x) = ½·erfc(−x/√2)
```

`erfc` is the Numerical Recipes Chebyshev fit, fractional error below 1.2 × 10⁻⁷
everywhere. That is ample here: it appears inside a Halley refinement, and in
Q-to-BER conversion where the answer spans decades and a part in 10⁷ is invisible.

For an NRZ link with Gaussian noise and a centred threshold, BER = Q(SNR).

### 6.3 Inverse normal CDF

Acklam's rational approximation followed by one Halley refinement step against the
true CDF. Relative error better than 10⁻¹⁵ over the whole range. This is the
function behind every bathtub curve on the site.

### 6.4 Dual-Dirac total jitter

```
TJ(BER) = DJ(peak-to-peak) + n(BER) · RJ_rms
n(BER)  = 2 · Q⁻¹(BER)
```

The factor of two is the two eye crossings, each contributing its own Gaussian tail;
the argument is the specified BER itself, not BER/2. That convention reproduces the
multiplier values quoted at the bench:

| BER   | n(BER) |
| ----- | ------ |
| 10⁻⁹  | 11.996 |
| 10⁻¹⁰ | 12.723 |
| 10⁻¹² | 14.069 |
| 10⁻¹⁶ | 16.444 |

> **Resolved at the Milestone 1 gate.** The convention above stands: the argument is
> the specified BER, and each of the two crossings is taken to contribute a tail of
> that probability. It is the convention that reproduces the table every scope's
> TJ@BER readout is quoted against, which is what makes a number on this site
> comparable with a number off an instrument.
>
> The BER/2 variant is real, and the difference it makes is small and one-directional
> — it is always the more pessimistic of the two:
>
> | BER   | n = 2·Q⁻¹(BER) | n = 2·Q⁻¹(BER/2) | difference |
> | ----- | -------------- | ---------------- | ---------- |
> | 10⁻⁹  | 11.9956        | 12.2188          | +1.86 %    |
> | 10⁻¹² | 14.0690        | 14.2610          | +1.37 %    |
> | 10⁻¹⁶ | 16.4442        | 16.6096          | +1.01 %    |
>
> A percent and a half on the RJ multiplier is far below the error in the
> extrapolation itself — dual-Dirac projects a 10⁻¹² number from perhaps 10⁻⁸ of
> measured data, and its accuracy is set by whether the bounded part is really
> bounded, not by which argument the Q-inverse takes. If a house convention needs the
> other form, it is one line in `dualDiracN`, and the doc comment there says so.

**Assumption:** the dual-Dirac model — deterministic jitter modelled as two impulses
separated by DJ(pk-pk), convolved with one Gaussian of width RJ_rms. It is an
extrapolation model, not a measurement. It is accurate when the deterministic jitter
really is bounded and the random part really is Gaussian, and it is optimistic when
a supposedly bounded mechanism is not actually bounded.

## 7. Windows and spectra

Implemented in [src/dsp/window.ts](src/dsp/window.ts).

Cosine-sum windows w[n] = Σ_k (−1)ᵏ a_k cos(2πkn/(N−1)) with the standard
coefficient sets (Hann, Hamming, Blackman, 4-term Blackman–Harris, flat-top), plus
Kaiser (I₀-based, adjustable β) and Tukey (tapered cosine).

Modified Bessel I₀ by series expansion; converges quickly over the β range in use.

| Window              | First sidelobe | Main lobe (−3 dB bins) | Use                                            |
| ------------------- | -------------- | ---------------------- | ---------------------------------------------- |
| Rectangular         | −13 dB         | 0.89                   | Whole number of cycles only                    |
| Hann                | −31 dB         | 1.44                   | General purpose                                |
| Hamming             | −43 dB         | 1.30                   | Low first sidelobe, slow far roll-off          |
| Blackman            | −58 dB         | 1.68                   | Small tone beside a large one                  |
| Blackman–Harris (4) | −92 dB         | 1.90                   | Spur far below a carrier                       |
| Flat top            | −69 dB         | 3.77                   | **Amplitude accuracy**, not resolution         |
| Kaiser              | adjustable     | ~1.7                   | Continuous trade via β                         |
| Tukey               | −15 dB         | ~1.0                   | Taper a response without touching its passband |

These sidelobe and main-lobe figures are the standard published properties of the
window functions, and the test suite verifies them numerically from the implemented
coefficients rather than trusting the table.

**Coherent gain** (mean of the window) and **noise power bandwidth**
(N·Σw² / (Σw)²) are computed from the actual coefficients, because they are the
correction factors needed to read an amplitude or a noise density off a windowed
spectrum, and using the wrong one is a silent scale error.

## 8. Convolution

Implemented in [src/dsp/convolve.ts](src/dsp/convolve.ts).

The channel is linear and time-invariant, so everything it does to a signal is
convolution with its impulse response. Three implementations, one dispatcher:

- **Direct** O(N·M) for short kernels, where its lower constant factor wins.
- **FFT** via zero-padding to at least N+M−1, multiply, inverse. The pad to
  N+M−1 is what makes it _linear_ convolution; without it the tail wraps onto the
  head, which in a channel response means the end of the record contaminating the
  start.
- **Overlap-add** for a long signal against a short kernel, so memory stays bounded
  when the record is a hundred thousand bits.

`circularConvolve` is provided separately and named honestly — it is the wrong
operation for a channel and the right one for a periodic pattern.

Correlation is convolution with one argument reversed and conjugated; the
zero-lag form is provided separately because it is the inner product and is the
hot path in tap estimation.

## 9. Interpolation and edge timing

Implemented in [src/dsp/interp.ts](src/dsp/interp.ts).

### 9.1 Reconstruction

| Method | Form                          | Correct when                                     |
| ------ | ----------------------------- | ------------------------------------------------ |
| Linear | straight line between samples | Never exactly; adequate at high oversampling     |
| Cubic  | Catmull–Rom                   | Smooth display of a smooth signal                |
| Sinc   | Σ x[n]·sinc((t−n))            | The signal is genuinely band-limited below f_s/2 |

sinc(x) = sin(πx)/(πx), with sinc(0) = 1 handled exactly rather than by limit.

Sinc reconstruction is the mathematically correct reconstruction of a band-limited
signal — and it **invents overshoot** on a signal that is not band-limited, which
is the reason a scope's sin(x)/x interpolation can show ringing that is not there.
Linear interpolation makes the opposite error: it understates peaks and overstates
rise time. Both are available, and Module 10 puts them side by side.

### 9.2 Threshold crossings

Sub-sample crossings by **linear** interpolation between the bracketing samples.
This is deliberate, not lazy: at 32+ samples/UI the edge is locally very close to
straight, and a higher-order fit can invent ringing near a noisy sample — a bias
that lands directly in the jitter histogram. Scopes make the same trade for the same
reason.

Hysteresis (as a fraction of full scale) suppresses double-counting on a noisy edge,
exactly as a scope's trigger hysteresis band does.

### 9.3 Rise time from a waveform

`edgeTransitionSamples` takes the low and high reference levels from the caller, so
both 10–90 % and 20–80 % are available. They are not interchangeable: on the same
edge, 20–80 % reads roughly 0.6× the 10–90 % figure, and datasheets quote both
without always saying which.

## 10. Hilbert transform and minimum phase

Implemented in [src/dsp/hilbert.ts](src/dsp/hilbert.ts).

### 10.1 Analytic signal

Zero the negative-frequency half of the spectrum, double the positive half, leave DC
and Nyquist alone, transform back. The result is x + j·H{x}; its magnitude is the
envelope and its phase derivative the instantaneous frequency.

Used for measuring the decay of ringing on an edge (Module 2), the shape of a
crosstalk pulse (Module 6), and the I/Q view of the same channel (Module 9).

### 10.2 Minimum-phase construction

For a causal, stable, minimum-phase system the log magnitude and the phase form a
Hilbert transform pair:

```
φ(ω) = −H{ ln|H(ω)| }
```

Computed via the real cepstrum: IFFT of ln|H|, apply the causal fold (keep c[0],
double the positive-quefrency half, zero the negative half), FFT back, exponentiate.

**Why it matters.** A magnitude-only loss model — skin effect plus dielectric loss —
has no phase of its own. Assuming linear phase instead of deriving it produces an
**acausal** impulse response: the channel responds before it is excited, and the
resulting eye diagram is wrong in a way that looks plausible. The minimum-phase
construction gives the unique causal response with the requested magnitude and the
least possible group delay.

**Limitation.** A magnitude floor (default −200 dB relative to peak) protects the
logarithm at deep nulls. A channel with a true transmission zero — a resonant stub —
is not minimum-phase, and its phase must be measured, not constructed. This is a
real restriction and Module 4 states it on screen.

## 11. Plotting mathematics

Not physics, but the same standard of correctness applies: a plotting error is
indistinguishable from a physics error to the reader.

### 11.1 Histogram bin centres

For n bins spanning [lo, hi], bin width w = (hi−lo)/n and centres at
lo + (i + ½)·w.

**The error this prevents:** using the bin _edges_ as centres shifts the entire
distribution left by half a bin. In a jitter histogram that is a systematic error in
the reported mean that nothing downstream would catch. The test suite asserts that
no centre ever coincides with an edge.

With an even bin count no bin is centred on zero, which is correct, and is why a
jitter mean must be computed from the samples rather than from the modal bin.

### 11.2 Eye folding

An eye diagram folds the record modulo the eye window (1 or 2 UI). A pattern whose
period equals the fold window produces **no overlay at all** — every trace lands on
top of the first one. This is the most common way an eye diagram lies, and it is
why the clock pattern and the eye window interact.

### 11.3 Eye measurements

- **Eye width** at the threshold measures the spread of the **crossings** — that is,
  jitter. It is not a rise-time measurement, and the two are routinely confused.
- **Eye height** at the sampling instant measures voltage margin at that instant
  only; quoted without its BER it means nothing (§6.4).
- On a noiseless eye the best sampling point is a **plateau**, not a point. Centring
  in the plateau rather than picking its maximum is exactly what memory read training
  does, and picking the argmax of a flat region is picking noise.

### 11.4 Colormaps

Viridis and Inferno are interpolated from control points at 0.1 intervals rather
than the full 256-entry matplotlib tables.

> **Known approximation.** Maximum deviation from the reference tables is small but
> non-zero, and perceptual uniformity is therefore approximate rather than exact.
> This is acceptable for density shading, where the reader compares relative
> density, and it would not be acceptable if a colour were being read as a value.
> Recorded in [PROGRESS.md](PROGRESS.md).

### 11.5 Per-division readouts

The "200 ps/div" figure is computed from the scale actually in use, dividing the
domain by the division count — never from a remembered setting, so the number in the
corner cannot drift away from the picture it annotates.

A **logarithmic** axis has no constant value per division, so no per-division figure
is printed for one. Quoting one would be the same category of error as averaging
decibels.

Everything raised for the Milestone 1 gate is closed. Kept here with its resolution,
because a decision with no record is a decision someone re-opens by accident.

1. **Gibbs constant — closed.** The exact 8.9490 % of the jump, not the brief's
   rounded 8.93 %. Re-derived from Si(π) in the test suite (§2.2).
2. **Dual-Dirac convention — closed.** n(BER) = 2·Q⁻¹(BER), the argument being the
   specified BER. The BER/2 variant differs by 1–2 %, always pessimistic, and is
   documented beside the implementation (§6.4).
3. **Clean brief — closed.** `BRIEF.md` is in the repository, the pasted copy's
   Latin-1 mis-decoding undone rather than retyped.
4. **Colormap approximation — standing limitation, not a question.** 0.1-interval
   control points rather than full 256-entry tables (§11.4). It is recorded in
   PROGRESS.md under known approximations, where it belongs: no plot on this site
   reads a colour as a value, and it would matter if one did.
